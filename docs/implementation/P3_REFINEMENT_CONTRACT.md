# P3 Plan refinement boundary

The browser key `fieldshift.plan-draft.v1` is retained so existing P2 drafts load. Payload version 1 migrates in memory to version 2 with `revision: 0` and all refinement answers unknown. Payload version 2 stores farmer reported sequence, water, goal, residue and feasibility answers. Changes increment the Plan revision; `isCurrentResult` and `acceptEvaluation` reject older result revisions. This draft is scoped to its selected place and is not a saved field record.

`FarmerDateInput` has exact, dekad and unknown variants. A dekad resolves to an interval, including the actual last day of the selected month. The adapter in `lib/plan/refinement-adapter.ts` emits a legacy `RotationSlot` input only for a confirmed sequence with valid exact planting and harvest dates in order. Otherwise it returns `needs-input` or `not-evaluable` with reasons. It never writes IndexedDB `field:<id>` or `rotation:<id>` records. Existing saved fields continue to use their exact-date schema unchanged.

The P3 comparison surface remains `regional-preview`. Qualitative water, priority and local feasibility answers are recorded for review but are not converted to millimetres, MCDA weights, or hard gates. The five feasibility answers are `needs-local-check` because this Plan path does not run tested enforcement for them. Risk has no matching `PriorityId`; it is recorded without ranking. Even when exact dates pass the adapter, a saved field and source evidence are still required before scientific field comparison. The regional catalog remains visible while that work is unavailable.
