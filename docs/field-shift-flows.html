Field Shift · UX and UI flows

How a farmer moves through Field Shift

Flows, drawn screens and the rules behind them: iOS-native behaviour, when to use flat surfaces and borders, how fields are managed, and how the layout responds. Screen numbers match PLAN.md; surface rules match DESIGN_SYSTEM.md. Numbers on the drawn screens are placeholders, never real output.

2. Three key screens, drawn

The product's difference is in three places: the best-match outline, the dashed amber unknown, and the hypothetical label that cannot be dismissed. Everything else stays quiet.

3. iOS-native behaviour: which container, when

Use the system pattern. A custom control is only justified where no system control can show season, calendar or scale data.

4. Borders and surfaces: when flat, when not

Start flat. Add a border, material or shadow only when it tells the farmer something that spacing cannot.

Flat fill
Flat (default)

Use for content: cards, lists, strips, charts.
Avoid for controls floating over a map.

Hairline 0.5 pt
Hairline

Use as row separators, inset to the text, and where a card sits on a same-coloured ground.
Avoid above the first or below the last row.

Accent 2 pt
Accent outline

Use for exactly one thing per screen: the best match.
Avoid for selection or focus (use the system ring).

Dashed amber
Dashed

Use only for unknown or not asked.
Never as decoration or for drafts.

Translucent control
Material / Liquid Glass

Use for tab bar, toolbars, floating map controls.
Never behind body text. Solid fallback with Increase Contrast.

System sheet
Elevated

Use only where the system already elevates: sheets, menus.
Never add shadows to cards.

QuestionAnswer
Two things look alike. Border or space?Space first. A border is the second tool.
Is the content over satellite imagery in sunlight?Solid surface, never glass. Contrast above 4.5:1.
Is it a status?Word, icon and shape together. Colour alone never carries meaning.
Is it destructive?Red, text only, away from the primary button, inside a confirmation. A stressed season is clay, not red.

5. Field management

Records stay on the phone. Only the field's location leaves it, and only after the farmer confirms "This is my field".

DraftOutline or point drawn. Nothing fetched.
ConfirmedLocation tick set. Data requests start.
ActiveHas a current crop, open questions, comparisons.

DeletedConfirmation says history exists only on this phone and will be lost.

6. Responsive layout

Adapt to the window, not the device. Selection and scroll position survive a resize. One column becomes sidebar, list and detail, then comparison columns with an evidence panel.

RuleDetail
AlignmentWhen options sit side by side, the same year lines up in every column. Faint vertical guides make that visible.
Large textRows stack, badges drop under the title, secondary toolbar actions move into a menu.
Pointer and keyboard⌘N new field, ⌘F search, hover states, right-click mirrors swipe actions, visible focus ring.
OfflineCached values appear immediately with "Updated 3 days ago". Never a blank screen while loading.

7. Honesty rules that shape every screen

RuleWhere it shows
Not known is not zeroAmber tag with a question mark, plus the question that would settle it.
Not asked is not a passDashed tag. It never dims or ranks an option.
Scale in wordsYour field · Village area · Wider area · Estimated map · Wider region on every finding.
Past, not future"Not a forecast" sits inline next to what it qualifies, never in a banner that can be closed.
Local judgement namedEach report ends with Check locally: variety, pests, buyer and price, land rules, flooding or frost.
Support, not replaceThe reminder repeats on every comparison and printed page: talk it through with an extension officer or an experienced farmer.
