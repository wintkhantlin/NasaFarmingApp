**Region-specific application of these same features**

- Ayeyarwady: use R and P within rice/black-gram/green-gram calendar windows; M provides regional post-monsoon moisture context. V supports crop transitions and possible low-cover intervals. Flooded rice/water pixels must not be classified as bare soil. Do not label residual field moisture sufficient from a 9 km SMAP pixel.
- Magway: use P heat/ETo and R rainfall/dry spells across sesame, groundnut, and the selected pulse's growth stages. M supplies regional moisture context. E is optional evidence on observed dates. The comparison needs crop-specific rooting/Kc and farmer water access.
- Shan: use T slope, V low-cover context, R rain and P temperature for maize/soybean/selected-cover-crop comparisons. A cover crop uses water and time; its presence must not be assumed to improve every priority. Coarse weather does not resolve each slope or valley.

**P: NASA POWER exact request and parameters**

Documentation: [Daily point API](https://power.larc.nasa.gov/docs/services/api/temporal/daily/), [parameter dictionary](https://power.larc.nasa.gov/parameters/).

Endpoint: [https://power.larc.nasa.gov/api/temporal/daily/point](https://power.larc.nasa.gov/api/temporal/daily/point)

| Query key | Value/format | Purpose |
|---|---|---|
| `parameters` | Comma-separated IDs in the next table | Select measurements |
| `community` | `AG` | Agricultural output conventions |
| `latitude`, `longitude` | Numeric WGS84 coordinates | Selected analysis point |
| `start`, `end` | `YYYYMMDD` | Requested dates |
| `format` | `JSON` or `CSV` | Output encoding |
| `time-standard` | `UTC` in the proposed integration | Align daily indexing with IMERG; UTC is not Myanmar local day |

| Exact parameter | Verified returned units | Application |
|---|---|---|
| `T2M` | C | Daily mean air temperature; climate profile and crop-rule inputs |
| `T2M_MAX` | C | Daily maximum air temperature; sourced heat thresholds |
| `T2M_MIN` | C | Daily minimum air temperature; cold/frost screening with local limitations |
| `RH2M` | % | Humidity input to documented ETo computation; not a fraction |
| `WS2M` | m/s | Wind at 2 m for ETo |
| `ALLSKY_SFC_SW_DWN` | MJ/m^2/day | Incoming shortwave solar energy; not net radiation |
| `PRECTOTCORR` | mm/day | Secondary rainfall source / explicitly labelled fallback |
| `PS` | kPa | Surface pressure; psychrometric calculations |

Developer-built request example; replace `lat` and `lon` with a verified farm location:

```python
import requests

def get_power(lat, lon, start="20250101", end="20251231"):
    response = requests.get(
        "https://power.larc.nasa.gov/api/temporal/daily/point",
        params={
            "parameters": "T2M,T2M_MAX,T2M_MIN,RH2M,WS2M,ALLSKY_SFC_SW_DWN,PRECTOTCORR,PS",
            "community": "AG", "latitude": lat, "longitude": lon,
            "start": start, "end": end, "format": "JSON", "time-standard": "UTC",
        }, timeout=120,
    )
    response.raise_for_status()
    return response.json()
```

Read `properties.parameter[PARAMETER][YYYYMMDD]`, returned `parameters` unit metadata, and `header.fill_value`. The verified response used `-999.0`; read the actual response instead of relying solely on this example. Never turn a fill value into zero rain. Cache requests and retain source/time-standard metadata.

P supports features 3–5, 7–9, 15, 17–18 and contextual parts of 22–24; its metadata supports 25–27.

[NASA data description](https://data.nasa.gov/dataset/gpm-imerg-final-precipitation-l3-1-day-0-1-degree-x-0-1-degree-v07-gpm-3imergdf-at-ges-dis-13ed8). | CMR query key | Value |
|---|---|
| `short_name` | `GPM_3IMERGDF` |
| `version` | `07` |
| `temporal` | `START_ISO_UTC,END_ISO_UTC` |

| `page_size` | e.g. `100` |
| `page_num` | Start at `1`; continue until exhausted, or use documented search-after pagination |

Discovery returns metadata/links, not a clipped rainfall time series. Obtain data via returned scientific-data links using Earthdata authentication as required by the provider. Daily files may cover the globe despite the search bounding box. Use provider subsetting or extract the nearest grid cell/area after download. Avoid downloading all global files for every farm.

| Raw scientific variable | Meaning / handling |
|---|---|
| `precipitation` | Daily precipitation rate, mm/day; represents a one-day estimate, not mm/hour |
| `precipitation_cnt` | Number of valid half-hour inputs underlying the daily rate; 48 is a complete day |
| `randomError` | Product's daily random-error estimate; read units in this daily file; not total uncertainty |
| `randomError_cnt` | Valid samples used for the error estimate |
| `lat`, `lon`, `time` | Grid coordinates and time; inspect dimension order and CF time metadata |

Read `_FillValue`, valid ranges, units and any scale metadata from the delivered file. Do not copy V06's `precipitationCal` into a V07 daily implementation. V07 daily estimates use valid half-hour samples and a full-day rate conversion; flag partial sampling rather than quietly interpreting it as a fully observed day. See the official product description linked above.

App-derived indicators: rain over the crop window, maximum consecutive dry days, heavy-rain days, and historical seasonal ranges. Dry/heavy thresholds must be named parameters with a source or clearly identified analyst assumption. Missing days break an evaluable dry-spell sequence; they are not dry days. Use common valid seasons across alternatives and report exclusions.

R supports features 3–9, 15–18, 20 and conditional weather context for 22–24; metadata supports 25–27. It cannot supply flood depth or a complete erosion-rainfall factor.

**V: NASA HLS Landsat bands**

Exact AppEEARS product: `HLSL30.020`. [Live layer metadata](https://appeears.earthdatacloud.nasa.gov/api/product/HLSL30.020). [NASA L30 description](https://hls.gsfc.nasa.gov/products-description/l30/). [HLS V2 user guide](https://lpdaac.usgs.gov/documents/1698/HLS_User_Guide_V2.pdf).

| Layer | Needed for |
|---|---|
| `B04` | Red reflectance for NDVI |
| `B05` | Near-infrared reflectance for NDVI and NDMI |
| `B06` | SWIR1 reflectance for NDMI, optional moisture-sensitive vegetation context |
| `B03` | Green reflectance if implementing a documented water-screening index |
| `B02` | Blue reflectance if implementing EVI; otherwise optional |
| `Fmask` | Cloud/shadow/snow/water/aerosol QA |

Raw reflectance scale: `0.0001`, offset `0`; raw fill `-9999`; Fmask fill `255`. Remove fill/saturation and invalid QA before indices. HLS is NOT raw USGS Collection 2 SR; do not apply the C2 factor `0.0000275` and offset `-0.2` to HLS.

```text
NDVI = (NIR - red) / (NIR + red)
NDMI = (NIR - SWIR1) / (NIR + SWIR1)
```

Handle zero/invalid denominators as missing. Proposed conservative QA policy: reject Fmask fill and cloud (bit 1), adjacent cloud/shadow (2), cloud shadow (3), snow/ice (4); separate water (5) from land-cover analysis and inspect aerosol flags (6–7). Bit 0 is reserved in HLS V2, not an active cirrus flag. Record the chosen policy. Water flags require care in rice systems: flooded crop periods are not bare soil.

Derive valid-observation vegetation profiles for polygons; report pixel counts and clear-observation coverage. Candidate low-cover intervals require multiple valid observations plus farmer dates/residue context. Do not infer a precise harvest date, disease or crop species from NDVI alone. NASA's catalogue may label the product temporal granularity “daily”; this does not promise daily clear observations at a field.

Supports features 1, 3, 6, 8–9, 15–17, 20–21 and 25–27. It provides historical cover context, not direct observation of a proposed future rotation.

Optional NASA HLS Sentinel-2 route: `HLSS30.020`, [metadata](https://appeears.earthdatacloud.nasa.gov/api/product/HLSS30.020), [band correspondence](https://hls.gsfc.nasa.gov/products-description/s30/). Equivalent red/NIR/SWIR1 are `B04`, `B8A`, `B11`, plus `Fmask`. In S30, `B05` is red-edge, not NIR. Use sensor-specific mappings if merging the two.

If retaining raw USGS Landsat instead, use global Collection 2 Level-2 with `SR_B4`, `SR_B5`, `SR_B6`, `QA_PIXEL`, `QA_RADSAT`; use its own scaling and QA. Access: [USGS data routes](https://www.usgs.gov/landsat-missions/landsat-data-access), [scaling](https://www.usgs.gov/faqs/how-do-i-use-a-scale-factor-landsat-level-2-science-products), [QA](https://www.usgs.gov/landsat-missions/landsat-collection-2-quality-assessment-bands). **Application calculations and required non-NASA inputs**

1. **Calendar and stage alignment (4, 5, 15, 17):** Store crop/variety, actual/planned sowing date, duration range, stage lengths, local planting window and next-crop deadline. Replay the proposed dates across comparable historical seasons; handle seasons crossing December and leap days explicitly. Regional crop categories are not varieties.
2. **Water comparison (7, 18):** Compute reference ETo with a documented method, then `ETc = Kc(stage) × ETo`. FAO Penman–Monteith additionally requires net-radiation/vapour-pressure calculations, latitude/date and elevation or pressure; shortwave radiation alone is not net radiation. Daily mean RH gives an approximation that must be disclosed. Method reference: [FAO-56](https://www.fao.org/4/x0490e/x0490e06.htm). Kc and stages require crop/variety evidence. ETc-minus-rain is only a screening metric; a root-zone balance needs available water capacity, effective rooting depth, initial field storage, irrigation, runoff/infiltration, drainage and relevant groundwater/capillary-rise treatment. Do not force unsupported soil parameters to defaults.
3. **Soil benefits (6, 19–21):** Report mechanism and evidence scope. Add nitrogen fixation ranges, grain/residue N removal, biomass/residue retention, soil carbon/depth/bulk density, rooting and management evidence where known. A planned cover interval is not measured ground cover; greenness is not soil organic matter.
4. **Pests/forage/economics (22–24):** Add host/family/disease-history rules, forage quality and suitability, local buyer/price information, yields and itemized costs. Do not link rainfall to profit via an unsourced yield-response formula.
5. **Recommendations and priorities (8–12):** Track feasibility first, then compare supported trade-offs against the farmer's priorities. Separate missing evidence from observed poor performance. Explain every assumption that can change preference; leave a choice unresolved when decisive evidence is missing.
